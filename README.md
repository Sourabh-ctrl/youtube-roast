# RoastTube

RoastTube signs a user in with Google, reads their own YouTube data with their
permission, and generates a playful, structured "roast" of their channel and
watch behavior. It is a portfolio/MVP project.

> **Disclaimer:** RoastTube is entertainment. It is not affiliated with, endorsed
> by, or sponsored by YouTube or Google. Roasts are generated by a language model
> from the user's own data and may be inaccurate or edgy by design.

---

## Features

- Google sign-in (OpenID Connect) with an optional, separate YouTube permission step.
- Reads the signed-in user's own channel stats, recent activity, and watch signals.
- Generates a structured roast report (scores, verdicts, advice) with a strict schema.
- Live progress while the report is generated, backed by real server-side stages.
- Report history with ownership checks and deletion.
- Minimal data retention and no third-party analytics.

## Prerequisites

- Node.js 20+
- A [Google Cloud](https://console.cloud.google.com/) project
- A MongoDB connection string ([MongoDB Atlas](https://www.mongodb.com/atlas) free tier works)
- An API key for an OpenAI-compatible chat completions endpoint (the default is [Groq](https://console.groq.com/))

### 1. Google OAuth

1. In Google Cloud Console, create a project and enable **YouTube Data API v3**.
2. Configure the **OAuth consent screen**. For local development use "External"
   and add yourself as a test user. Request these scopes:
   - `openid`, `email`, `profile`
   - `https://www.googleapis.com/auth/youtube.readonly`
3. Create an **OAuth client ID** of type **Web application**.
4. Add **Authorized redirect URIs** (exact match, no trailing slash):
   - `http://localhost:5000/auth/google/callback`
   - your production backend callback, e.g. `https://<backend>.vercel.app/auth/google/callback`
5. Add **Authorized JavaScript origins** for the frontend origins you use
   (`http://localhost:5173`, `https://<frontend>.vercel.app`).

## Local setup

```bash
# 1. Install dependencies for both packages
npm run install:all

# 2. Create env files
#    Copy server/.env.example -> server/.env and fill it in
#    Copy client/.env.example -> client/.env
```

`server/.env`:

```dotenv
NODE_ENV=development
PORT=5000
CLIENT_URL=http://localhost:5173

GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
GOOGLE_CALLBACK_URL=http://localhost:5000/auth/google/callback

AI_API_KEY=...                       # Groq API key
AI_MODEL=openai/gpt-oss-120b
AI_BASE_URL=https://api.groq.com/openai/v1

MONGODB_URI=mongodb+srv://...
MONGODB_DB=roasttube
SESSION_SECRET=...                   # >= 32 characters
SESSION_STORE_URI=                   # optional; falls back to MONGODB_URI
```

`client/.env`:

```dotenv
VITE_API_BASE_URL=http://localhost:5000
```

Run both dev servers (two terminals):

```bash
npm run dev:server   # http://localhost:5000
npm run dev:client   # http://localhost:5173
```

## Deployment

The project deploys as **two Vercel projects** from the same repository: one for
`client/`, one for `server/`. Vercel provides HTTPS, which is required for the
production cookie and OAuth settings.

### Frontend (Vercel)

- **Root directory:** `client`
- **Build command:** `npm run build` (auto-detected for Vite)
- **Output directory:** `dist`
- **Environment variable:** `VITE_API_BASE_URL=https://<backend>.vercel.app`
- `client/vercel.json` rewrites all paths to `/index.html` so client-side routing works.

### Backend (Vercel)

Vercel detects the Express app from `server/src/index.js`, which default-exports
the app and connects to MongoDB. No build settings are needed; the function runs
on Fluid compute with a 300s default timeout, which comfortably covers AI
generation.

- **Root directory:** `server`
- **Environment variables:** everything from the server table above, with:
  - `NODE_ENV=production`
  - `CLIENT_URL=https://<frontend>.vercel.app`
  - `GOOGLE_CALLBACK_URL=https://<backend>.vercel.app/auth/google/callback`
- Add that same production callback to the Google OAuth client's redirect URIs.

Production cookies are already configured for cross-site use
(`SameSite=None; Secure`), and the server trusts Vercel's proxy so secure cookies
are set. Requirements for sign-in to work across the two domains:

- The frontend origin in `CLIENT_URL` matches the deployed frontend exactly
  (scheme + host, no trailing slash).
- The browser sends credentials (the client uses `withCredentials: true`).
- Both sites are served over HTTPS (Vercel default).

### Notes specific to the serverless backend

- **Sessions and reports require MongoDB.** Without a reachable `MONGODB_URI`
  the app cannot start in production, because the in-memory session store is
  only meant for local development and tests.
- **The roast job registry is in-memory.** The background job is kept alive with
  Vercel's `waitUntil`, so the report finishes and is saved. Polling a job on a
  different cold-started instance can return `JOB_NOT_FOUND`; for high traffic,
  move job state to a shared store (MongoDB/Redis) or a queue.
- **The rate limiter is in-memory per instance.** Limits are approximate across
  instances and reset on cold starts.

## Security and privacy

- Only the user's own data is read, and only with their explicit YouTube consent.
- OAuth tokens and the AI key never reach the browser; the client bundle contains
  no secrets.
- Sessions use an HTTP-only cookie; OAuth `state` is validated to prevent CSRF.
- Non-idempotent API calls require a same-origin `Origin` header.
- Responses carry `helmet` security headers.
- Retention is minimal: reports and users are stored in MongoDB and can be
  deleted from the app; sessions expire after 7 days.

## Troubleshooting

| Symptom | Likely cause / fix |
| ------- | ------------------ |
| `CORS_ORIGIN_DENIED` | `CLIENT_URL` does not exactly match the frontend origin. |
| Signed in locally but `UNAUTHENTICATED` in production | Cookie not sent cross-site: check `CLIENT_URL`, HTTPS, and that the client sends credentials. |
| `redirect_uri_mismatch` from Google | `GOOGLE_CALLBACK_URL` must exactly match a registered redirect URI. |
| `YOUTUBE_PERMISSION_REQUIRED` | The user has not granted YouTube access yet; the app prompts for it. |
| `AI_TIMEOUT` / slow generation | The AI endpoint was slow or unreachable; check `AI_API_KEY`/`AI_BASE_URL` and the function `maxDuration`. |
| `JOB_NOT_FOUND` | The job expired or was polled on a different serverless instance (see notes above). |
| Server exits on boot | Missing/invalid env; `loadEnv()` requires a MongoDB URI outside `test`. |
